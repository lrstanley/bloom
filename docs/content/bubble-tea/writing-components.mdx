A component you already have, with a `View() string` method, goes in a bloom layout with
[`bloom.View`](/bubble-tea/bubbles-components), as a Bubbles component does. This page is about components built
for bloom: ones that change shape with their size, handle their own clicks, and can appear more than once on a
screen. A component like that returns bloom nodes from a `Layout` method, and doesn't need a `View` at all.

It builds a row of tabs as the example. The [complete component](#the-complete-component) is at the end.

## Lay out for the space you're given

A [`bloom.Child`](https://pkg.go.dev/bloomfx.dev/bloom#Child) is anything with a `Layout` method that returns a
bloom layout. bloom calls it with a [`bloom.Context`](https://pkg.go.dev/bloomfx.dev/bloom#Context), whose `Width`
and `Height` methods return the space it has:

```go
type Tabs struct {
	Labels []string
	Active int
}

func (t *Tabs) Layout(ctx bloom.Context) bloom.Child {
	// Not room for every label in full. A width of zero is its natural size.
	w := ctx.Width()
	short := w > 0 && w < t.width()
	tabs := make([]bloom.Child, len(t.Labels))
	for i, label := range t.Labels {
		if short {
			label = ansi.Truncate(label, 1, "")
		}
		style := tabStyle
		if i == t.Active {
			style = activeStyle
		}
		tabs[i] = bloom.Text(label).Style(style)
	}
	return bloom.Row(tabs...)
}
```

```
 inbox  sent  drafts     wide enough
 i  s  d                 narrow
```

`Layout` may be called more than once a frame, while bloom measures as well as for the final layout, so it must not
change the component. Treat it like `View`: read state, return nodes. [Responsive layouts](/layout/responsive) has
more on changing shape with size.

A component that needs no type of its own, such as one piece of a screen that changes with its width, can be a
[`bloom.LayoutFunc`](https://pkg.go.dev/bloomfx.dev/bloom#LayoutFunc): a function with the same signature as
`Layout`, placed as a child.

### Read only the sizes you use

bloom notes which of `ctx.Width()` and `ctx.Height()` a component calls, and lays it out again only when one of
those changes. `Tabs` reads only its width, so measuring it at several heights lays it out once. A component that
reads neither is laid out once a frame wherever it's placed, and so are the components it returns. Read a size
only where the layout depends on it, and `Layout` must depend on nothing else but the component's state.

### Draw it where a string is wanted

bloom never needs a `View` from a component with a `Layout`. If the component is also used where a string is
wanted, such as by a program that doesn't use bloom, give it a `View` that draws its layout with
[`bloom.Render`](https://pkg.go.dev/bloomfx.dev/bloom#Render), which with a size of zero draws it at its natural
size:

```go
func (t *Tabs) View() string {
	return bloom.Render(0, 0, t)
}
```

`Render` keeps nothing between calls. For a view drawn every frame, keep a
[`*bloom.Root`](https://pkg.go.dev/bloomfx.dev/bloom#Root) in the component and call its `Render`, which skips
drawing a frame that didn't change.

## Report a natural size

A component with a `View` is measured by rendering its view, and one with a `Layout` by measuring the nodes it
returns. When it knows its size without that, it can say so by implementing
[`bloom.Measurer`](https://pkg.go.dev/bloomfx.dev/bloom#Measurer). A status bar is one row tall at any width:

```go
type statusbar struct{ text string }

func (s statusbar) View() string { return " " + s.text }

func (s statusbar) Measure(bloom.Size) bloom.Size {
	return bloom.Size{W: lipgloss.Width(s.View()), H: 1}
}

// in View
bloom.Column(bloom.Fill(body), bloom.View(m.status))
```

bloom checks for `Measurer` on the component inside a `bloom.View` too.

Return the size the component needs, not the space it's offered: when a layout is drawn at its natural size, the
space offered is unbounded. The result is clamped to the space there is.

## Handle the mouse inside the component

A component can put [mouse handlers](/input/mouse) on the nodes it returns, so the parent doesn't need to know
where its parts are. A handler can change the component, as long as it reaches the real one rather than a copy:
give the component pointer receivers, and put a pointer to it in the tree.

```go
tabs[i] = bloom.Text(label).Style(style).
	On(on.Click(func() tea.Cmd { return t.pick(i) }))
```

```go
func (t *Tabs) pick(i int) tea.Cmd {
	t.Active = i
	id := t.ID
	return func() tea.Msg { return TabMsg{ID: id, Active: i} }
}
```

The handler changes the tabs, then returns a command that tells the parent, which handles `TabMsg` in its `Update`
like any other message. The parent keeps the tabs by value and places a pointer to them:

```go
type model struct {
	ui   *bloom.Root
	main Tabs
	// ...
}

// in View
bloom.Column(bloom.Auto(&m.main), bloom.Fill(body))
```

With value receivers, the click changes a copy and does nothing. If a component must be kept by value, such as one
written for Bubble Tea's usual `m.c, cmd = m.c.Update(msg)` pattern, have its handlers send a message with `on.Msg`
and change state in its own `Update` instead. See
[Change state, or send a message](/input/mouse#change-state-or-send-a-message).

Place the component as the type its `Layout` method is on. `Layout` is on `*Tabs`, so `m.main` in place of `&m.main`
isn't a `bloom.Child`, and doesn't compile.

### Read the frame from a handler

A component has no root to ask where things went, so its handlers read the frame from the `Context` that `Layout`
was given. `ctx.Frame()` returns the frame on screen when it's called, which in a handler is the frame the event
landed in. Called from `Layout` itself, it's the frame before, and outside a root, such as with `Render`, it's nil.
A [list in a component](/content/lists#lists-in-components) uses it to scroll from where the list actually was.

### Know which side a layer opened on

A component drawn in a layer [anchored](/layers/dropdowns) to a node can ask `ctx.Side()` which side of the node the
layer was placed against, which flips when it doesn't fit. A dropdown uses it to draw its open edge facing its
field.

## Give each instance its own IDs

[IDs](/concepts/how-a-program-runs#ids) must be unique in a frame, and two instances of `Tabs` on one screen would
otherwise give their nodes the same ones. Have each instance make an ID of its own with
[`bloom.NewID`](https://pkg.go.dev/bloomfx.dev/bloom#NewID) when it's made, and build the IDs of its parts from it
with [`Sub`](https://pkg.go.dev/bloomfx.dev/bloom#ID.Sub):

```go
type Tabs struct {
	ID     bloom.ID // unique to this instance
	Labels []string
	Active int
}

// NewTabs returns tabs with the labels, and an ID of their own.
func NewTabs(labels ...string) Tabs {
	return Tabs{ID: bloom.NewID("tabs"), Labels: labels}
}

// in Layout
tabs[i] = bloom.Text(label).Style(style).ID(t.ID.Sub(i))
// ...
return bloom.Row(tabs...).ID(t.ID).Focusable()
```

`NewID` never returns the same ID twice, whatever the name, so two `Tabs` never clash, and neither do their tabs. The
ID is a plain field, so a copy of the component keeps it, as Bubble Tea's copies of the model do. The parent makes
each instance once, such as when it makes the model:

```go
m.main = NewTabs("inbox", "sent", "drafts")
m.side = NewTabs("people", "labels")
```

The component's root node joins the parent's [focus](/input/focus) order, and the parent can find a tab by its ID,
such as with `m.ui.Frame().Rect(m.main.ID.Sub(1))`.

## Place components you're given

A container, such as a stack of panels, places children it didn't build. It can still make some of them focusable,
and keep that apart from the code that decides how each is placed: wrap a child that should take focus in an
[`Auto`](https://pkg.go.dev/bloomfx.dev/bloom#Auto) slot with its ID before placing it. Here the children say
whether they take focus by implementing an interface of the container's:

```go
// Focuser is a child of a Stack that takes focus, by the ID it returns.
type Focuser interface {
	bloom.Child
	FocusID() bloom.ID
}

// focusable makes c a stop in the tab order if it's a Focuser.
func focusable(c bloom.Child) bloom.Child {
	if f, ok := c.(Focuser); ok {
		return bloom.Auto(c).ID(f.FocusID()).Focusable()
	}
	return c
}
```

Outside a row, column, or grid, a slot's sizing does nothing: it takes the space its parent gives it and passes it
on, so the wrapped child is laid out as it would be without the slot. In a row or column, the container places it in
a slot of its own, which decides the size. A grid sizes a slot in its cell as a row would, so in a grid, place it in
a `Fill` to fill the cell:

```go
// in a column, the outer slot decides the size
bloom.Column(bloom.Fixed(3, focusable(s.header)), bloom.Fill(focusable(s.body)))

// in a list, each item is whatever item returns
bloom.List(len(s.items), func(i int) bloom.Child { return focusable(s.items[i]) })

// in a grid, a Fill fills the cell
bloom.Grid(2, bloom.Fill(focusable(s.left)), bloom.Fill(focusable(s.right)))
```

Wrap the child, rather than adding the ID to the slot it's placed in. A [list](/content/lists) has no slot for each
item, and the code that picks `Fixed` or `Fill` stays the same whether or not a child takes focus. A child that marks
its own nodes focusable, as `Tabs` does, needs no wrapping.

## Take keys from the parent

Keys aren't routed to nodes; they go to the parent's `Update`. Give the component an `Update` method of its own, and
have the parent call it while the component has focus. For a click on the tabs to focus them, give the root the
parent's focus with [`bloom.WithFocus(&m.focus)`](https://pkg.go.dev/bloomfx.dev/bloom#WithFocus):

```go
// Update moves between tabs with the arrow keys.
func (t *Tabs) Update(msg tea.Msg) tea.Cmd {
	if msg, ok := msg.(tea.KeyPressMsg); ok {
		switch msg.String() {
		case "left":
			return t.pick(max(t.Active-1, 0))
		case "right":
			return t.pick(min(t.Active+1, len(t.Labels)-1))
		}
	}
	return nil
}
```

```go
	case tea.KeyPressMsg:
		cmd, ok := m.focus.Update(msg, m.ui.Frame())
		if !ok {
			switch m.focus.Current() {
			case m.main.ID:
				cmd = m.main.Update(msg)
			case m.side.ID:
				cmd = m.side.Update(msg)
			}
		}
```

Pass on any other messages the component needs, such as its own `TabMsg` or animation frames, the same way. See
[Route keys to the focused node](/input/focus#route-keys-to-the-focused-node).

## The complete component

```go title="tabs.go"
package main

import (
	"bloomfx.dev/bloom"
	"bloomfx.dev/bloom/on"
	tea "charm.land/bubbletea/v2"
	"charm.land/lipgloss/v2"
	"github.com/charmbracelet/x/ansi"
)

var (
	tabStyle    = lipgloss.NewStyle().Padding(0, 1)
	activeStyle = tabStyle.Reverse(true)
)

// Tabs is a row of tabs, one of which is active.
type Tabs struct {
	ID     bloom.ID // unique to this instance
	Labels []string
	Active int
}

// NewTabs returns tabs with the labels, and an ID of their own.
func NewTabs(labels ...string) Tabs {
	return Tabs{ID: bloom.NewID("tabs"), Labels: labels}
}

// TabMsg is sent when the user picks a tab.
type TabMsg struct {
	ID     bloom.ID
	Active int
}

// Layout shows each label in full when there's room, and only its first
// letter when there isn't.
func (t *Tabs) Layout(ctx bloom.Context) bloom.Child {
	w := ctx.Width() // zero is its natural size
	short := w > 0 && w < t.width()
	tabs := make([]bloom.Child, len(t.Labels))
	for i, label := range t.Labels {
		if short {
			label = ansi.Truncate(label, 1, "")
		}
		style := tabStyle
		if i == t.Active {
			style = activeStyle
		}
		tabs[i] = bloom.Text(label).Style(style).ID(t.ID.Sub(i)).
			On(on.Click(func() tea.Cmd { return t.pick(i) }))
	}
	return bloom.Row(tabs...).ID(t.ID).Focusable()
}

// Update moves between tabs with the arrow keys. The parent calls it while
// the tabs have focus.
func (t *Tabs) Update(msg tea.Msg) tea.Cmd {
	if msg, ok := msg.(tea.KeyPressMsg); ok {
		switch msg.String() {
		case "left":
			return t.pick(max(t.Active-1, 0))
		case "right":
			return t.pick(min(t.Active+1, len(t.Labels)-1))
		}
	}
	return nil
}

func (t *Tabs) pick(i int) tea.Cmd {
	t.Active = i
	id := t.ID
	return func() tea.Msg { return TabMsg{ID: id, Active: i} }
}

// width is how wide the tabs are with their full labels.
func (t *Tabs) width() int {
	w := 0
	for _, label := range t.Labels {
		w += ansi.StringWidth(label) + tabStyle.GetHorizontalFrameSize()
	}
	return w
}
```

A test can click a tab by its ID, with [`m.ui.Click`](/bubble-tea/testing):

```go
m.View()
if _, ok := m.ui.Click(m.main.ID.Sub(1)); !ok || m.main.Active != 1 {
	t.Fatal("the sent tab was not picked")
}
```
