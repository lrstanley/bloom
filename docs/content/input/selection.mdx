---
title: Selecting and copying text
description: Let the mouse select text in the nodes you choose, as a terminal does but kept inside them, read what's selected, and copy it with OSC 52 or the system clipboard.
---

Once a program turns on mouse reporting, the terminal stops selecting text itself: the mouse events go to the
program instead. bloom brings selection back, for the nodes you make selectable. A selection stays inside the node
it started in, so dragging down a log in one pane doesn't run into the sidebar beside it, and it reads the text the
node holds, not the cells on screen, so it can take lines scrolled out of sight and leave out a box's border.

The [selection example](https://github.com/lrstanley/bloom/tree/master/_examples/selection) has a selectable log,
a pane of fields, wrapped text, a dialog with a masked token, notes that scroll their own text, an input that keeps
its own selection, and a list of ten thousand requests:

![The selection example: lines of a log dragged over and copied, a rectangle of timestamps selected with alt held, a selection across a request's fields, words selected with a double click, all of the log selected and copied, a token selected inside a dialog over the log, notes selected and scrolled away with the wheel, text selected in an input with shift and the arrows, typed over, and double clicked, and rows of a list of requests selected, scrolled away with the wheel while held, and copied whole](/demos/selection.webp)

## Make text selectable

`Selectable()` lets the left button select text in a node. Every node has it, from text and boxes to
[viewports](/content/viewports) and [lists](/content/lists), except a `Drawable`, a `Scrollbar`, and a `TooltipSink`,
which have no text of their own:

```go
bloom.Box(panel, bloom.Column(fields...).Selectable())
```

A selection can run across every node inside the selectable one, such as from a label into the value beside it,
but not out of it. On a box, only what's inside its frame is selected. When selectable nodes are inside each other,
the innermost one under the pointer takes the drag.

Selecting needs drag events, which `tea.MouseModeCellMotion` reports. The view from `m.ui.View` asks for it while
any node is selectable.

Pass every message to `m.ui.Update` and return its command, as you do for the rest of bloom: the root keeps the
selection, and sends itself ticks while selecting.

## How the mouse selects

| Gesture | Selects |
| --- | --- |
| drag | a run of text, in reading order, as a terminal does |
| <kbd>alt</kbd> held as the drag starts | a rectangle of cells, such as a column of timestamps |
| double click | a word |
| triple click | a line; in a viewport, the whole line of its buffer, on every row it wraps to |
| click | nothing, and clears what was selected |

A double click finds words as Unicode does, and joins them across `@-./_~?&=%+#`, so a path, a URL, or an email
address is one word. `bloom.WithWordChars(chars)` changes those characters, and `""` leaves words as Unicode finds
them:

```go
ui := bloom.New(bloom.WithWordChars("-_"))
```

In a viewport, a double click finds the word in the buffer's text rather than in the cells of the row, so a word
that wraps across rows is selected whole. A buffer can have word characters of its own, set with
`buf.SetWordChars(chars)`, which its viewport uses in place of the root's. `Buffer.WordAt`, `NextWord`, and
`PrevWord` find words with the same characters as the double click does, the buffer's or else the root's: see
[words](/input/editing#words).

## Read what's selected

When a drag that selected some text ends, the root sends a [`bloom.SelectionMsg`](https://pkg.go.dev/bloomfx.dev/bloom#SelectionMsg) with the text, and the ID of the node
it was selected in, or of its nearest ancestor with one:

```go
case bloom.SelectionMsg:
	m.status = fmt.Sprintf("selected %d characters in %v", len(msg.Text), msg.ID)
```

After a double click, the message waits until a third click could no longer widen the selection to the line.

`m.ui.Selection()` returns the text selected at any time, and whether any is. The selection stays until the next
click, `m.ui.ClearSelection()`, or a copy.

### What text is read

A selection reads the text of the nodes it covers, rather than the cells drawn:

- All of a `Text`, including the lines scrolled out of sight in a [`Scroll`](/content/scrolling).
- Text wrapped to fit, joined back into the lines it was.
- Text [cut short with `Truncate`](/content/text#keep-text-on-one-line), copied whole.
- A viewport's lines, including those scrolled away, without its line numbers and gutters.
- What a component draws, read from its cells, or what it says it shows, if it implements
  [`TextSource`](#components-that-know-their-text).
- The text of a component that scrolls or wraps its own, if it implements
  [`TextMap`](#components-that-scroll-their-own-text), or that edits it, if it implements
  [`Editable`](#components-that-edit-their-text).
- Every item of a [list](/content/lists) the selection covers, including those scrolled out of view: see
  [Selections in a list](#selections-in-a-list).

What's drawn around the text, such as a box's border, padding, and the edges on it, isn't selected.

## Copy it

`m.ui.CopySelection()` copies the selection to the clipboard, clears it, and sweeps a band across the text it
copied, to show what went. It returns `nil` when nothing is selected, so <kbd>ctrl+c</kbd> can copy, or quit with
nothing to copy:

```go
case tea.KeyPressMsg:
	switch msg.String() {
	case "ctrl+c":
		if cmd := m.ui.CopySelection(); cmd != nil {
			return m, cmd
		}
		return m, tea.Quit
	}
```

To copy as soon as text is selected, as many terminals do, copy when the message arrives:

```go
case bloom.SelectionMsg:
	return m, m.ui.CopySelection()
```

### Where the text goes

The text is sent to the terminal's clipboard with OSC 52, which reaches the clipboard of the machine the terminal
runs on, even over SSH. Not every terminal allows it, and those that do don't answer, so there's no telling whether
it arrived.

[`bloom.WithClipboard(write)`](https://pkg.go.dev/bloomfx.dev/bloom#WithClipboard) writes to the system clipboard as well, first, with a function you give it, such as one
that runs `wl-copy`, `xclip`, or `pbcopy`. A function that can't reach a system clipboard, such as over SSH, should
return `nil` and leave the copy to OSC 52:

```go
ui := bloom.New(bloom.WithClipboard(func(text string) error {
	cmd := exec.Command("wl-copy")
	cmd.Stdin = strings.NewReader(text)
	return cmd.Run()
}))
```

A `bloom.CopyMsg` arrives once the text is copied, with what the function returned in `Err`:

```go
case bloom.CopyMsg:
	m.status = fmt.Sprintf("copied %d characters", len(msg.Text))
	if msg.Err != nil {
		m.status += " with OSC 52 only: " + msg.Err.Error()
	}
```

`bloom.WithCopyFlash(false)` turns the band off. It also doesn't sweep while motion is off; see
[turning motion off](/motion/animating-values#turn-motion-off).

## Select all, and clear

`m.ui.SelectAll(id)` selects all the text of the node with an ID, or of the selectable node it's in, including what's
scrolled out of sight. It reports whether there was such a node with text in the last frame, and can be copied at
once. No `SelectionMsg` is sent for it:

```go
case "ctrl+a":
	m.ui.SelectAll(paneLog)
case "esc":
	m.ui.ClearSelection()
```

## Select past the edge

Dragging past the edge of what's shown of a selectable node scrolls it while the pointer is held there,
the way the wheel would:

- A [viewport](/content/viewports#select-text) scrolls through its `OnScroll`.
- Text in a [`Scroll`](/content/scrolling) scrolls through the `on.Scroll` handler on the node around it, the one the
  wheel uses.
- A [list](/content/lists) scrolls through its `on.Scroll` handler, and the selection takes each item that scrolls
  into view.

```go
bloom.Fixed(10, bloom.Scroll(bloom.Text(m.help).Selectable(), m.offset)).
	On(on.Scroll(func(_, dy int) tea.Cmd { m.offset = min(max(m.offset+dy, 0), m.maxOffset); return nil }))
```

The selection is kept on the text it covers, so it moves with the text as it scrolls, and stays when it's scrolled
out of sight.

## Selections in a viewport

A viewport keeps its selection as places in its buffer's text, not as cells, so the selection stays on the same
text whatever happens around it:

- Scrolled either way, or resized so its lines wrap differently, or switched to another `Wrap` mode.
- Lines appended, as a log grows, or its first lines taken out, as a [capped log](/content/viewports#cap-a-log)
  takes them.
- The buffer edited before the selection, inside it, or after it, with `Replace`, `Insert`, `Delete`, or `Edit`.

`SetContent`, `SetLines`, `Clear`, and `Restore` replace the text the selection was in, so they clear it. A
selection reads its text from the buffer, and draws over only the rows in sight, so selecting all of a million
lines costs no more to draw than selecting a screenful.

A rectangle selected with <kbd>alt</kbd> held keeps its corners on the rows they started on, and is worked out
again from where those rows are drawn each frame.

## Selections in a list

A list builds only the items in view, however many it has. A selection in it keeps the item each of its ends is in,
by the item's index, so it stays when those items scroll out of view and is drawn again where it was when they
scroll back. Whatever is in view between the ends is drawn as selected: with the start scrolled away above, every
item shown up to the end.

The text selected is that of every item the selection covers, built or not, in order, a line to an item. The items
that aren't in view are built when the text is read, by `m.ui.Selection()`, `m.ui.CopySelection()`, or the
`SelectionMsg` a drag sends, at the width the list was laid out at, and only then: drawing a frame costs no more
with an end of the selection far out of view than with both in view. The list's item function is called then, in
`Update`, so until the next frame it has to give the items as they were drawn. The text is kept until then, so
reading it again, as `m.ui.CopySelection()` does after a `SelectionMsg`, builds nothing more.

When an item can tell its text without being built, `ItemText` gives it, for the items selected whole. It must
return what selecting all of the item would, with its rows a line each and the nodes side by side in a row joined
with a space. The two items the selection starts and ends in are still built, since each end is a place in its
item as laid out:

```go
bloom.List(len(m.rows), m.row).Offset(m.offset).Selectable().
	ItemText(func(i int) string { return m.rows[i].name + " " + m.rows[i].size })
```

`SelectAll` takes every item, and reads none until the text is wanted, so it's as cheap on a million items as on a
screenful.

A selection follows its items by index. When the list's items change, it stays on the same indexes, as it does
while they're in view, and it ends when an index it's in is past the new count, or when the list leaves the frame.

A rectangle selected with <kbd>alt</kbd> held is of the cells in view. While one of its corners is scrolled out of
the list, nothing is selected, and scrolled back, it's there again. A drag that ends with a corner out of view
selects nothing.

## Clicks and drags in selectable nodes

Selecting and clicking share the left button, so bloom sorts them out:

- A press that moves before it comes up selects; one that doesn't is a click, and runs the click handlers of what's
  under it, such as a row's `on.Click`.
- A node inside with an [`on.Drag`](/input/mouse#drag) handler, such as a splitter or a slider, takes its drags, and
  doesn't select.
- A double or triple click in a selectable node selects the word or line, and doesn't click.

So that double clicking a word doesn't also click the row it's in, a click inside a selectable node waits until it
can no longer become a double click, 400ms, before its handlers run. `bloom.WithClickDelay(false)` runs clicks at
once, and a double click is then two clicks. Make only the nodes people read selectable,
rather than the whole screen, and buttons elsewhere answer at once.

## Selections and layers

A selection in a [layer](/layers/dialogs) stays inside it, so a dialog's text can be selected over the log it covers.
Make the layer selectable to select across all of what's in it:

```go
bloom.Layer(bloom.Box(dialog, body)).ID("dialog").Selectable().Modal()
```

A layer opening over a selection leaves it as it was, under the layer. A selection ends when its node leaves the
frame, such as a dialog closing.

## Change how it looks

By default, selected cells get a background between the terminal's own background and foreground, and keep their
foregrounds where they can be read on it. `bloom.WithSelectionStyle(style)` draws them in a style of your own. A
color the style leaves unset is kept from each cell, so a background alone keeps the colors of highlighted code:

```go
ui := bloom.New(bloom.WithSelectionStyle(lipgloss.NewStyle().Background(selectionBg)))
```

A foreground kept that would be hard to read on the background, such as a dim one, takes the terminal's foreground
or background instead, whichever reads better.

## Components that know their text

A component's text is read from the cells it draws. When that isn't the text to copy, such as a token it shows
masked, or a decoration it draws around its text, implement `bloom.TextSource`. `SelectedText` gets the `Span`
selected, in cells from the component's top-left, and returns the text for it:

```go
type secret struct{ value string }

func (s secret) View() string {
	return s.value[:4] + strings.Repeat("•", len(s.value)-4)
}

// SelectedText implements bloom.TextSource: the token is one row, a
// character to a cell.
func (s secret) SelectedText(span bloom.Span) string {
	from, to := span.Start.X, span.End.X+1
	if span.Start.Y > 0 {
		from = len(s.value)
	}
	if span.End.Y > 0 {
		to = len(s.value)
	}
	from, to = min(from, len(s.value)), min(to, len(s.value))
	return s.value[from:max(to, from)]
}
```

`Start` and `End` are the first and last cells selected, inclusive. `Block` is set for a rectangle, and `Size` is
the size the component was laid out at, to wrap its text the same way again. A component that implements
`TextSource` is selectable without being made so.

## Components that scroll their own text

`TextSource` suits a component whose text is its cells. A component that shows a window of its text, with its own
scroll offset, or wraps its text itself, needs the selection kept on its text instead, so that it follows the
text as the component scrolls and reaches the text out of sight. Implement `bloom.TextMap`, and tell bloom where in
your text each cell is:

```go
// PosAt returns the position of the character drawn at cell: the end of
// the row for a cell past its text, the start of the row in a gutter.
func (r *reader) PosAt(cell image.Point, size bloom.Size) bloom.Pos

// Cells calls row for each row in sight that the text from from up to to
// covers, with the cells of it it takes, from x0 up to x1.
func (r *reader) Cells(from, to bloom.Pos, size bloom.Size, row func(y, x0, x1 int))

// Text returns the text from from up to to.
func (r *reader) Text(from, to bloom.Pos) string
```

A `bloom.Pos` is a line of your text and a byte of that line, as in a [buffer](/content/viewports#edit-the-text).
`to` and `x1` are exclusive. bloom may pass positions past the end of a line or of the text, for "to the end", so
clamp them.

bloom keeps the selection, and does the rest: it draws the selection over the cells `Cells` reports, after your
component draws, copies what `Text` returns, finds words in the cells as drawn, and takes a line whole on a triple
click. Dragging past the component's edge scrolls it through the `on.Scroll` handler under the pointer, for as long
as the pointer is held there, since bloom can't tell how much text is out of sight:

```go
bloom.Fill(m.reader).ID("notes").
	On(on.Scroll(func(_, dy int) tea.Cmd { m.reader.scroll(dy); return nil }))
```

A component that implements `TextMap` is selectable without being made so, and a selection can run into it, or
through it, from a `Text` beside it inside a larger selectable node. Holding <kbd>alt</kbd> selects as a drag does
in it, since a rectangle of cells is more than the three methods tell. The selection ends when the component leaves
the frame. If its text changes under a selection, clearing the selection is up to you.

## Components that edit their text

An editor or an input has a caret, which is one end of its selection, and the keyboard makes and moves the
selection as often as the mouse does. To edit the lines of a `Buffer`, give a viewport a caret, which does all of
this for you: see [Editing text](/input/editing). For a component of your own, implement `bloom.Editable`, a
`TextMap` that keeps its own range, with its caret at `Head`:

```go
// Selection returns what is selected, an empty range at the caret when
// nothing is.
func (f *field) Selection() bloom.Range { return f.sel }

// Select sets what is selected, from the mouse.
func (f *field) Select(r bloom.Range) { f.sel = f.clamp(r) }
```

Place it in the layout by pointer, such as `bloom.Fill(&m.input)`, so that `Select` reaches the model's copy.

The mouse sets the range through `Select`, as an editor does:

| Gesture | Does |
| --- | --- |
| click | puts the caret under the pointer |
| <kbd>shift</kbd> held with a click | moves the caret there, and keeps the anchor |
| drag | selects from the caret at the press to the caret under the pointer |
| double click, triple click | selects the word, as drawn, or the line |

A `TextMap` tells positions in its text, and not which side of a wrap a caret is drawn on, so the ranges the mouse
gives your component leave `EndOfRow` unset.

bloom reads `Selection` every frame, and draws a range that holds text in the selection's style: your component
draws no highlight of its own. Only one selection is shown at a time. Starting one anywhere else collapses the
range to its caret, and a range your component makes itself, such as with <kbd>shift</kbd> and an arrow, becomes
the selection and clears any other, as soon as bloom sees it. `m.ui.Selection()` and `m.ui.CopySelection()` see it
in the same `Update` that made it:

```go
case "shift+left":
	m.input.sel.Head.Col = max(m.input.sel.Head.Col-1, 0)
	if text, ok := m.ui.Selection(); ok {
		m.status = fmt.Sprintf("selected %q", text)
	}
```

`CopySelection` copies the range and leaves it selected, sweeping the band across it. `ClearSelection` collapses it
to its caret, and `SelectAll` with the ID of the node it's in selects all of it. A `SelectionMsg` is sent for what
the mouse selects, not for what your component selects.
