---

[`bloom.Focus`](https://pkg.go.dev/bloomfx.dev/bloom#Focus) keeps track of which node has keyboard focus,
by ID. It lives in your model. The layout marks which nodes can take focus, and the order they appear in the
layout is the tab order.

## Make nodes focusable

Focus refers to nodes by [ID](/concepts/how-a-program-runs#ids), so give everything that can take focus an ID. A
constant for each node keeps them in one place:

```go
const (
	fieldName    bloom.ID = "name"
	fieldEmail   bloom.ID = "email"
	buttonSave   bloom.ID = "save"
	buttonCancel bloom.ID = "cancel"
)
```

Add a `bloom.Focus` to your model. Its zero value has nothing focused:

```go
type model struct {
	ui     *bloom.Root
	focus  bloom.Focus
	values map[bloom.ID]string
	// ...
}
```

Then mark the nodes `Focusable`:

```go
bloom.Text(m.values[fieldName]).Style(input).ID(fieldName).Focusable()
bloom.Text(m.values[fieldEmail]).Style(input).ID(fieldEmail).Focusable()
```

Focus moves between focusable nodes with IDs, and passes over those without one. Any node can be focusable,
such as a slot: `bloom.Fill(m.editor).ID(paneEditor).Focusable()` makes a whole pane a stop in the tab
order. A component that places children it was given can make them focusable the same way; see
[Place components you're given](/bubble-tea/writing-components#place-components-youre-given).

## Move focus with tab and clicks

`m.focus.Update(msg, m.ui.Frame())` handles <kbd>tab</kbd> and <kbd>shift+tab</kbd>. It returns a command, and
reports whether it handled the message:

```go
	case tea.KeyPressMsg:
		cmd, ok := m.focus.Update(msg, m.ui.Frame())
		if !ok {
			cmd = m.key(msg) // other keys, for whatever has focus
		}
		return m, tea.Batch(cmd, m.ui.Update(msg))
```

`m.ui.Frame()` is the layout of the last frame drawn, which has the nodes that can be focused and their order.
Focus wraps around from the last node to the first.

To move focus to what's clicked, give the root your focus with [`bloom.WithFocus`](https://pkg.go.dev/bloomfx.dev/bloom#WithFocus):

```go
func newModel() *model {
	m := &model{}
	m.ui = bloom.New(bloom.WithFocus(&m.focus))
	return m
}
```

A click then focuses the innermost focusable node under the pointer, then runs [mouse handlers](/input/mouse), so
a handler can move focus again, as a "next" button would. The root keeps a pointer to your `Focus`, so keep the
model behind a pointer too.

You can also move focus yourself: `Set(id)`, `Next(frame)`, `Prev(frame)`, and `Clear()`. `Set` doesn't check the
node: it can be one that isn't focusable, or is outside the current scope, and `Is` reports it focused anyway. `Next` and `Prev`
report whether they found a node to move to.

## Press buttons with the keyboard

A button made with [`on.Press`](https://pkg.go.dev/bloomfx.dev/bloom/on#Press) runs its handler when
clicked, and when <kbd>enter</kbd> or <kbd>space</kbd> is pressed while it has focus. `m.focus.Update` runs it for
the keys, and returns its command with `ok` set:

```go
bloom.Text("save").Style(button).ID(buttonSave).Focusable().On(on.Press(m.save))
```

Enter and space on a focused node without a `Press` handler aren't handled, so they reach your own key handling,
such as to type a space into an input.

## Style the focused node

`m.focus.Is(id)` reports whether a node has focus, so `View` can style it:

```go
func (m *model) field(id bloom.ID) bloom.Child {
	style := input
	if m.focus.Is(id) {
		style = inputFocused
	}
	return bloom.Text(m.values[id]).Style(style).ID(id).Focusable()
}
```

## Route keys to the focused node

`m.focus.Current()` returns the focused node's ID, or `""` while nothing is focused, which matches none of your
constants:

```go
		switch id := m.focus.Current(); id {
		case fieldName, fieldEmail:
			m.values[id] += msg.Text
		}
```

### Many nodes of one kind

When there are many of a kind, such as the rows of a table, give each an ID made with
[`Sub`](/concepts/how-a-program-runs#keep-ids-apart) from one ID of their own. To know which row is focused, keep
each row's ID with it, and look for the focused one:

```go
var rowIDs = bloom.NewID("row")

type row struct {
	id   bloom.ID // rowIDs.Sub(key), made with the row
	name string
}
```

```go
		id := m.focus.Current()
		if i := slices.IndexFunc(m.rows, func(r row) bool { return r.id == id }); i >= 0 {
			return m, m.open(i)
		}
```

## Show the cursor in an input

`Cursor` on a text node shows the terminal's cursor at a position inside the node. Put it after the text of each
input:

```go
// one column in, for the style's left padding
in := bloom.Text(value).Style(style).ID(id).Focusable().
	Cursor(tea.NewCursor(1+ansi.StringWidth(value), 0))
```

The position is relative to the node's top-left cell, wherever it ends up on screen. The cursor is hidden while a
layer covers that cell. `ansi` here is `github.com/charmbracelet/x/ansi`, which measures the width of text the way
the terminal does.

The terminal has only one cursor, so bloom shows one. With [`WithFocus`](#move-focus-with-tab-and-clicks), it
shows a cursor inside a focusable node only while that node is focused, so every input can give its cursor, and the
cursor follows the focus. The cursor can be on the focusable node itself or anywhere inside it, such as on the text
in a focusable box. The node that decides is the nearest focusable one with an ID: a focusable node without one,
which `Focus` passes over, doesn't hide the cursor. A cursor in no such node is shown too, unless the focused node's
cursor is in sight; of those, the one drawn last is shown. Without `WithFocus`, bloom shows the cursor drawn last, so give it only to the focused input:

```go
in := bloom.Text(value).Style(style).ID(id).Focusable()
if m.focus.Is(id) {
	in = in.Cursor(tea.NewCursor(1+ansi.StringWidth(value), 0))
}
```

For Bubbles text inputs, use the cursor the component reports; see
[Using Bubbles components](/bubble-tea/bubbles-components#show-the-terminal-cursor).

## Keep focus inside a dialog

While a dialog is open, <kbd>tab</kbd> should only move between its buttons. A **scope** confines focus to the
focusable nodes inside it. Modal layers with an ID are scopes:

```go
// confirmDialog is never shown, so NewID keeps it apart from any button,
// even one called "confirm".
var confirmDialog = bloom.NewID("confirm")

bloom.Layer(dialog).ID(confirmDialog).Modal()
```

`Push(scope)` confines focus to the scope and clears it, and remembers what was focused before. `Pop()` leaves the
scope and focuses that node again:

```go
func (m *model) openDialog() tea.Cmd {
	m.focus.Push(confirmDialog)
	m.focus.Set(buttonCancel)
	return m.confirm.Show()
}

func (m *model) closeDialog() tea.Cmd {
	m.focus.Pop()
	return m.confirm.Hide()
}
```

Scopes nest, so a dialog opened from a dialog pushes a second scope, and closing it returns to the first.
`m.focus.Scope()` returns the innermost scope pushed, which tells you which dialog is on top.

## Group a panel into a scope

Slots can be scopes too, with `Scope()`. Without pushing it, a scope lets you ask whether focus is somewhere in a
part of the screen, such as to highlight a panel's border while any field in it is focused:

```go
bloom.Fixed(60, form).ID(scopeForm).Scope()
```

```go
if m.focus.Within(m.ui.Frame(), scopeForm) {
	border = activeBorder
}
```
