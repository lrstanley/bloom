description: Animate nodes and layers in and out with effects, combine and sequence effects, and open a dialog from the button that was pressed.

A **transition** draws a node with [effects](/reference/effects) applied to its cells, for a progress from 0 to 1.
At 0 the node is just starting to enter, and at 1 it's fully shown, exactly as it would be without the effect. Feed
the progress from an [animated value](/motion/animating-values) and the node animates.

The [transitions example](https://github.com/lrstanley/bloom/tree/master/_examples/transitions) loops a gallery of effects and combinators, then opens dialogs from
their buttons:

![The transitions example: a gallery of transitions entering and leaving, then dialogs opening with an iris and unfolding from the button that was used](/demos/transitions.webp)

## Three ways to apply one

| Where | Use |
| --- | --- |
| A layer that comes and goes | `bloom.Layer(c).Presence(p, effects...)` |
| A layer that comes and goes, played by `Root` | `bloom.Layer(c).ID(id).Enter(opts, effects...).Exit(opts, effects...)` |
| A node in a layout that comes and goes | `bloom.Present(p, c, effects...)` |
| Any node, with any progress | `bloom.Transition(t, c, effects...)` or `bloom.Layer(c).Transition(t, effects...)` |

The `Presence` forms take an [`anim.Presence`](https://pkg.go.dev/bloomfx.dev/bloom/anim#Presence) and
leave the node out completely while it's hidden. A hidden `Present` node takes no space in its row or column and
leaves no gap behind. A hidden layer has no backdrop, no shadow, and doesn't take mouse events.

```go
// a dialog
bloom.Layer(dialog).Presence(m.dialog, fx.Fade{}, fx.Slide{From: bloom.Bottom})

// a details panel that slides open below a list
bloom.Column(
	list,
	bloom.Present(m.details, bloom.Box(panel, details), fx.Wipe{From: bloom.Top}),
)
```

Something shown with a presence takes no input while it animates out: its handlers don't run, and its nodes can't
be focused, selected, or show tooltips.

The `Transition` forms draw the node whatever the progress is. Use them for effects that run on something that's
always there, or with progress you compute yourself:

```go
bloom.Transition(m.reveal.Float(), chart, fx.Typewriter{})
```

## Pick a direction

Effects that travel across a node, `Slide`, `Wipe`, `Decode`, `Blinds`, `Wave`, and `Shimmer`, take a `From`
direction: a side, or a corner to run diagonally.

```go
fx.Wipe{From: bloom.TopLeft}       // reveals from the top left corner to the bottom right
fx.Decode{From: bloom.Left}        // rows decode into place from the left
fx.Slide{From: bloom.BottomRight}  // moves in from beyond the bottom right corner
```

Leaving `From` out uses the effect's default, such as `Bottom` for a slide and `Top` for `Decode`'s rain. Matching
the direction to where something came from makes the motion read as a move: an item that shifts left to make room
can decode in from the right.

## Showing and hiding use the same effects

When a presence hides, its progress runs back from 1 to 0, so the effects play in reverse: a dialog that slides up
from the bottom slides back down. You don't need separate exit effects.

If you want something to leave differently from how it came in, choose the effects from its state:

```go
effects := []fx.Effect{fx.Fade{}, fx.Slide{From: bloom.Bottom}}
if !m.dialog.Shown() { // animating out
	effects = []fx.Effect{fx.Fade{}}
}
bloom.Layer(dialog).Presence(m.dialog, effects...)
```

## Let Root play a layer's entrance and exit

A presence is state your model keeps and updates. For a layer that's simply drawn while it's open, such as a
dialog or a menu, `Enter` and `Exit` let [`Root`](/bubble-tea/root) play its transitions instead: it notices by
the layer's ID when the layer appears and when it's gone, so nothing in your model, or in the components the layer
is made of, has to know it animates.

```go
timing := []anim.Option{anim.Duration(300 * time.Millisecond), anim.Ease(anim.Linear)}
fly := fx.Fly{From: fx.Middle, Plain: true}

var layers []bloom.LayerNode
if m.confirming {
	layers = append(layers, bloom.Layer(confirm).ID(confirmID).Enter(timing, fly).Exit(timing, fly))
}
bloom.Overlay(page, layers...)
```

When `m.confirming` turns true, the dialog flies out of the middle of the screen. When it turns false, `Root` keeps
showing what the dialog last showed, flying back in, then drops it. Nothing in the dialog is drawn again, so its
components can go away with it. While it exits it takes no input: what's beneath it gets clicks at once. It stays
where it was among the overlay's layers, so a toast declared after it still covers it. Drawing a layer with the
same ID again while it exits brings it back from where it got to.

The options configure the progress, as for [`anim.NewValue`](https://pkg.go.dev/bloomfx.dev/bloom/anim#NewValue),
and the enter and exit can differ, such as a quicker exit. The layer's backdrop and shadow follow the progress, so
a dimmed backdrop fades in and out with it.

`Root` has to be able to follow the frame a layer appears on with another, so a layer is shown at once, rather than
entering, on the first frame, on a frame of a new size, and when its overlay wasn't on screen the frame before.
Keep the `Overlay` in the tree with no layers, rather than leaving it out, for a layer to enter the first time it's
drawn. A layer exits only while its overlay stays on screen, where it was in the tree, or with the same ID.

## Combine effects

Effects given together are applied in order, all with the same progress. `fx.Fade{}, fx.Slide{From: bloom.Bottom}`
fades in while sliding up. `fx.Scramble{}, fx.Fade{}` settles random glyphs into the text while it fades in.

Put `Fade` after effects that change glyphs or move cells, such as `Scramble`, `Decode`, and `Fly`. For the first
half of its progress, `Fade` shows the glyphs beneath the node in its cells, so an effect after it changes those
instead: `fx.Fade{}, fx.Scramble{}` scrambles what's beneath the dialog, not the dialog.

The [`fx`](https://pkg.go.dev/bloomfx.dev/bloom/fx) package has four combinators for finer control:

### Cascade with Stagger

`Stagger` splits a node into rows or columns, and runs an effect on each one after the other. A list sliding in
one item at a time:

```go
fx.Stagger{Effect: fx.Slide{From: bloom.Left}, From: bloom.Top}
```

`From` is the side the first part is at. `Top` and `Bottom` split the node into rows, `Left` and `Right` into
columns, and a corner counts as its top or bottom side. The default is `Bottom`, which starts with the last row.
`Spread` is how much of the progress is spent starting the parts: the default, 0.5, starts the last part when the
first is halfway done.

### Run in sequence with Delay

`Delay` runs an effect over part of the progress only. Several delays in a row play one after another:

```go
bloom.Layer(card).Presence(m.card,
	fx.Delay{Effect: fx.Fade{}, To: 0.5},              // fade in over the first half
	fx.Delay{Effect: fx.Scramble{Seed: 5}, From: 0.5}, // then unscramble the text
)
```

### Run backward with Reverse

`Reverse` runs an effect with the progress flipped, for a node leaving while the progress rises:

```go
bloom.Transition(m.leaving.Float(), oldPage, fx.Reverse{Effect: fx.Wipe{From: bloom.Left}})
```

### Change the curve with Ease

`Ease` runs an effect with eased progress, using any easing function, such as those in `anim`:

```go
fx.Ease{Effect: fx.Slide{From: bloom.Left}, Easing: anim.OutBack} // overshoots, then settles
```

Easing the effect is different from easing the presence: the presence's progress drives the backdrop and every
effect, while `fx.Ease` changes one effect only. `Ease` holds a function, which Go can't compare, so a frame using
it is redrawn every time even when nothing changed. That's fine while it animates; avoid leaving it on a node that
sits still.

## Open a dialog from its button

`fx.Iris` reveals a node through a growing circle, and `fx.Fly` flies its cells out of one spot. Start either on
the button that was pressed and the dialog appears to open out of it. Find the button in the last frame when it's
pressed:

```go
bloom.Text("share").ID(buttonShare).On(on.Press(m.openShare))
```

```go
func (m *model) openShare() tea.Cmd {
	if r, ok := m.ui.Frame().Rect(buttonShare); ok {
		m.shareFrom = image.Pt((r.Min.X+r.Max.X)/2, (r.Min.Y+r.Max.Y)/2)
	}
	return m.share.Show()
}
```

```go
bloom.Layer(shareDialog).Presence(m.share, fx.Iris{From: fx.At(m.shareFrom)})
```

Both take an [`fx.Origin`](https://pkg.go.dev/bloomfx.dev/bloom/fx#Origin) as `From`: `fx.At(p)` for a cell in
screen coordinates, such as the button's middle or where a click was, `fx.Side(d)` for a side or corner of the node,
or `fx.Middle`. `Iris` starts in the middle without one. A menu opened with a right click can fly out of the click:

```go
bloom.Layer(menu).ID(menuID).Enter(timing, fx.Fly{From: fx.At(m.clickedAt), Plain: true})
```

## Random effects stay steady

Effects with randomness, like `Dissolve`, `Scramble`, `Shade`, `Decode`, and `Glitch`, take a `Seed`. The same
seed gives the same pattern on every frame, so the effect doesn't flicker as it runs. Change the seed to vary it,
such as one per dialog or one per time it opens.
