---
title: Layout animation
description: Make slots and layers move and resize smoothly whenever the layout changes, with Animate, and no animation state in your model.
---

When a panel opens, a list re-sorts, or a split changes ratio, the layout jumps to its new shape on the next frame.
Add `.Animate()` to a slot or layer and bloom glides it there instead, reflowing its content at each size along
the way. Your model only holds the application state, such as whether the sidebar is open, and no animation
values.

```go
width := 0
if m.sidebarOpen {
	width = 24
}

bloom.Row(
	bloom.Fixed(width, sidebar).ID("sidebar").Animate(),
	bloom.Fill(content).ID("content").Animate(),
)
```

Toggle `m.sidebarOpen` and the sidebar slides open or closed while the content resizes to match.

The [reflow example](https://github.com/lrstanley/bloom/tree/master/_examples/reflow) animates a sidebar, a re-sorting list, a changing split, and a panel coming and
going this way:

![The reflow example: the sidebar closing and opening, the list re-sorting, the split changing ratio, and the details panel coming and going, each gliding into place](/demos/reflow.webp)

## Requirements

Layout animation is kept by the `*bloom.Root` between frames, so it needs three things:

- **An ID** on each animated slot or layer, so bloom can match it from one frame to the next.
- **A `Root`**, rendering with `m.ui.View`. `bloom.Render` and `bloom.Solve` don't keep state between calls, and
  always show the final layout.
- **Every message passed to `m.ui.Update`**, with its command returned. That's what schedules frames while
  anything is moving:

```go
func (m *model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
	cmd := m.ui.Update(msg)
	// ...
	return m, cmd
}
```

## What animates

- A slot moving to a new place, such as list items re-sorting, glides there. Give each item an ID that stays with
  the item, not with its position, like its name or database ID.
- A slot changing size grows or shrinks, and its children lay out again at each intermediate size.
- A slot whose size becomes zero, like the closed sidebar above, animates closed rather than vanishing.
- A layer anchored to a node, such as a marker [anchored](/layers/dropdowns#follow-the-node) to the selected row,
  follows it smoothly from row to row.

Some changes happen at once: a [collapsed](/layout/responsive) slot, a node removed from the tree, and a layer whose
anchor disappears are gone on the next frame.

## Choose the motion

`Animate` takes the same options as an [animated value](/motion/animating-values). The default eases over 250
milliseconds; a spring suits things that move often, because it keeps its momentum when the target changes
mid-flight:

```go
bloom.Fixed(width, sidebar).ID("sidebar").Animate(anim.Spring(16, 0.85))

bloom.Layer(marker).
	AnchorTo(selected, bloom.Right).
	ID("marker").
	Animate(anim.Spring(20, 1))
```

The options are captured when the ID first appears, so changing them later has no effect on a node already on
screen. The frame rate and clock come from the root, set with
[`bloom.WithFPS`](https://pkg.go.dev/bloomfx.dev/bloom#WithFPS),
[`bloom.WithUnfocusedFPS`](https://pkg.go.dev/bloomfx.dev/bloom#WithUnfocusedFPS), and
[`bloom.WithClock`](https://pkg.go.dev/bloomfx.dev/bloom#WithClock). Layout animation also stops when
[motion is turned off](/motion/animating-values#turn-motion-off).

## Move with effects

Rather than gliding, a slot or layer can snap to its new place and have effects draw it on its way there. Add
`MoveWith` after `Animate`, whose options then time the effects, as their progress runs from 0 to 1:

```go
bloom.Fill(pane).
	ID(id).
	Animate(anim.Duration(800*time.Millisecond), anim.Ease(anim.Linear)).
	MoveWith(fx.Fly{})
```

[`fx.Fly`](https://pkg.go.dev/bloomfx.dev/bloom/fx#Fly) starts the slot out whole where it was, then flies
its cells over, a column at a time, as bright glyphs that arc over and land where it goes. A slot that changed size
starts out squeezed or stretched to the size it was.

The slot is laid out where it goes from the first frame, so its content lays out once, at its new size, and
`m.ui.Frame().Rect(id)` reports its new place. Only its cells are on their way, drawn over the rest of its
container, such as the panes it passes; a layer's are drawn over the layers before it, and under those after it.
A slot or layer at rest costs no more than any other, and nothing is kept between frames to draw it on its way.

A slot still gliding finishes its glide first, such as a [dragged](/input/mouse#drag) layer with the same ID that was
just dropped into its place. A slot that changes between gliding and moving with effects carries on from where it
was last laid out. To move slots your own way, write an effect that
[draws a node on its way](/motion/custom-effects#draw-a-node-on-its-way).

## Geometry while animating

`m.ui.Frame().Rect(id)` reports where a node was drawn on screen, so mid-animation it's the in-between
rectangle. A node that [moves with effects](#move-with-effects) is laid out where it goes from the first frame, so
it reports that. `bloom.Solve` reports where the layout is headed. Use `Solve` when you need final sizes in `Update`,
such as to [size a Bubbles component](/layout/bubbles-components).

## When to use a Value instead

`Animate` covers layout: position and size. Use an [`anim.Value`](/motion/animating-values) when you need the
number in your model, such as to drive an effect, to read the progress, or to animate something that isn't a
rectangle.
