---
title: Troubleshooting
description: Fixes for common problems, such as a blank screen, clicks that don't arrive or arrive twice, text that can't be selected, animations that don't move, text that doesn't wrap, and more.
---

Most problems come down to one of three things: a message that never reaches `m.ui.Update`, a node without the ID
or handler you thought it had, or a handler that changes a copy of your model. Start with `bloom.Debug` to see what
the layout did, then find your symptom below.

## See what the layout did

[`bloom.Debug`](https://pkg.go.dev/bloomfx.dev/bloom#Debug) lays out a tree like `Solve` and returns it as
text: every node, how it's sized, its ID, and where it went. Nodes that were collapsed, scrolled away, or only partly
on screen are marked, and so is a node with the same ID as one before it, as `duplicate`. Write it somewhere you can read while the program runs, such as a log file:

```go
func (m model) View() tea.View {
	if m.debug {
		log.Print(bloom.Debug(m.width, m.height, m.layout()))
	}
	return m.ui.View(m.width, m.height, m.layout())
}
```

```text
Column 0,0 30x5
├─ Row 0,0 30x3
│  ├─ Fixed(10) id="sidebar" hidden collapsible=1
│  │  └─ Box hidden
│  │     └─ Text "Inbox" hidden
│  └─ Fill id="reader" 0,0 30x3 min=24
│     └─ main.reader 0,0 30x3
└─ Text "ready" 0,3 30x1 truncate
```

Rectangles are `x,y` then `width x height`. `Debug` is stateless, so layout animations show where they're headed, not
where they are mid-flight, and effects that move a node, such as `fx.Slide`, aren't applied. The format is for
reading, and may change between versions.

## The screen is blank

`m.ui.View` draws nothing while the width is zero, which it is until Bubble Tea sends the first
`tea.WindowSizeMsg`. Store the size from that message in your model and pass it to `View`:

```go
case tea.WindowSizeMsg:
	m.width, m.height = msg.Width, msg.Height
```

## Clicks don't arrive

Check each of these:

- Mouse reporting is on. The view from `m.ui.View` turns it on for the handlers in its frame; if you set
  `v.MouseMode` yourself, it needs at least `tea.MouseModeCellMotion` (or `tea.MouseModeAllMotion` for hover).
- The handler is on the node, or on something it's inside, with `On(...)`.
- A node inside it doesn't have a handler of the same kind. The innermost one takes the event; see
  [which node gets the event](/input/mouse#which-node-gets-the-event).
- A click runs when the button comes up over the node it went down on. Releasing it elsewhere cancels the click.
- A modal layer isn't open, taking the events.
- The view comes from `m.ui.View(...)`, which installs the `OnMouse` handler that runs your handlers. If you build
  the `tea.View` yourself or replace its `OnMouse`, pass every message to `m.ui.Update`, which then runs them.

## Tooltips never show

Check each of these:

- The root has [`WithTooltips`](/input/tooltips#turn-tooltips-on), or `m.ui.EnableTooltips(true)` was called.
  Without either, `Tooltip(...)` does nothing.
- Every message reaches `m.ui.Update`, and its command is returned. The wait before a tooltip shows is a command,
  and a tooltip opens when its message comes back through `Update`.
- The view reports all mouse motion. `m.ui.View` asks for it while the frame has a tooltip; if you set
  `v.MouseMode` yourself, set it to `tea.MouseModeAllMotion`. Under `tea.MouseModeCellMotion`, terminals report the
  pointer only while a button is held, so only [keyboard tooltips](/input/tooltips#reach-tooltips-from-the-keyboard)
  show.
- The pointer moved onto the node. A tooltip opens only on motion, not when a new frame puts the node under a still
  pointer, and not again after a key, click, or wheel event closed it until the pointer has left the node.
- For cut text: it was actually cut, with "…", and it isn't inside a `NoTooltip()` node, and `Truncated` isn't
  `TipOff`. `m.ui.Frame().Truncated(id)` tells you whether it was cut.
- A modal layer isn't open over the node.
- The mode for that kind isn't `TipHidden`, or `TipSink` with a `TooltipSink` on screen you aren't looking at.
- For the focus: the root has `WithFocus`, and the focus moved onto the node with a key press. A click that focuses a
  node doesn't show its tooltip.

## A handler runs, but nothing changes

Handlers are closures made in `View`, so they change whatever `View` captured. If that's a copy, the change is
lost:

- `View` has a value receiver, `func (m model) View()`. Use a pointer receiver, or have the handler send a message
  with `on.Msg(msg)` and change the state in `Update`.
- The handler is built in a component kept by value in its parent, such as a Bubbles-style list updated with
  `m.list, cmd = m.list.Update(msg)`. Have the component send a message with `on.Msg` and handle it in its own
  `Update`, or build the handler in the parent over `&m.list`.

See [change state, or send a message](/input/mouse#change-state-or-send-a-message).

## Every click happens twice

Your handlers run, and the original `tea.MouseClickMsg` reaches `Update` too. If you also handle the raw mouse
messages, don't act on an event a handler already handled.

## Clicks are slow inside selectable text

A click inside a node made [selectable](/input/selection) waits until it can no longer become a double click, so
that double clicking a word doesn't also click what it's in. Make only the text people read selectable, rather than
the whole screen, or turn the wait off with `bloom.WithClickDelay(false)`.

## Text can't be selected or copied

Once a program turns on mouse reporting, the terminal stops selecting text itself. Most terminals still select
while <kbd>shift</kbd> is held, or <kbd>option</kbd> in some on macOS. To select inside the program, mark the nodes
`Selectable()` and copy with `m.ui.CopySelection()`; see [Selecting and copying text](/input/selection).

If a copy doesn't reach the clipboard, the terminal may not allow OSC 52, or may need it turned on in its settings.
Give the root a system clipboard to write to with [`bloom.WithClipboard`](https://pkg.go.dev/bloomfx.dev/bloom#WithClipboard).

## The screen freezes after a click

A handler runs on the Bubble Tea event loop, the same as `Update`, so it must not block: no sleeping, waiting, or
I/O in the handler itself. Return a command for that work instead, which runs in the background.

## Animations don't move, or stop partway

- Return the command from `Show`, `Hide`, `To`, `Play`, and `Loop`. Without it, the first frame is never scheduled.
- Pass **every** message to every animation, with `anim.Update(msg, &m.a, &m.b)`, and return its command. Passing
  only some message types drops the frame messages.
- For layout animation (`Animate`), pass every message to `m.ui.Update` and return its command, and give the
  animated slot or layer an ID.
- Animations in a slice need to be updated through pointers to the elements, as in
  [stacking toasts](/layers/toasts#stack-several-toasts).
- Check that nothing called `anim.SetMotion(false)`; see [turning motion off](/motion/animating-values#turn-motion-off).

## Effects look wrong on a light terminal

`Dim` fades toward the terminal's background, and some effects use its foreground. Until the terminal reports its
colors, bloom assumes white on black. Return `m.ui.Init()` from your model's `Init` and pass every message to
`m.ui.Update` so the root hears the reply. For terminals that never answer, set defaults with `bloom.WithColors`.

## Text doesn't wrap, or wraps when it shouldn't

- `bloom.Text(s)` wraps to the width its node is given. Text that runs off the edge instead has `.NoWrap()`, or is in
  a node that gives it as much width as it wants, such as a `Scroll` with `X`.
- A status bar or title that should stay on one line needs `.Truncate()`.
- Preformatted text, such as ASCII art or a table, that should be cut off at the edge rather than wrapped needs
  `.NoWrap()`.
- A string you rendered yourself with Lip Gloss has a fixed size already. Pass the style to `Text(...).Style(...)` or
  `Box(...)` instead, so bloom renders it at the right size.

## A panel disappears

A `Collapsible` slot is dropped when the minimum sizes in its row or column don't fit. Lower another slot's `Min`,
raise the collapsible slot's priority, or make the terminal bigger. `m.ui.Frame().Rect(id)` reports `false` for a
collapsed slot, which you can use to tell the user the panel is hidden.

## Rect, Click, or focus can't find a node

IDs are compared by value and type. A node given `.ID(paneSidebar)`, where `paneSidebar` is a `pane`, isn't found
with `Rect("sidebar")`, and a `Focus[control]` passes over nodes whose IDs aren't `control`s. Use the same typed
constants in the layout and where you look the node up. A node in a [collapsed slot](#a-panel-disappears), or not in
the last frame drawn, isn't found either. See [IDs](/concepts/how-a-program-runs#ids).

## Tab doesn't move focus

The node needs `Focusable()` and an ID of the type your `Focus` holds, and `Update` has to pass key presses to
`m.focus.Update(msg, m.ui.Frame())`. While a dialog's scope is pushed, focus stays inside it. See
[Focus and keyboard navigation](/input/focus).

## A component has the wrong size

Components that size themselves internally, such as a Bubbles viewport, need to be told the size their slot has.
Find it with `bloom.Solve` when the window size or layout changes; see
[Using Bubbles components](/bubble-tea/bubbles-components#give-a-component-its-size). Remember that a slot's rectangle
includes the border of a `Box` inside it.

## Wide characters look misaligned

bloom measures text with grapheme clustering by default, as Lip Gloss does. If your terminal measures emoji or other
wide characters differently, set the method to match with `bloom.WithWidthMethod`.
