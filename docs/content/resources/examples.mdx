The repository's [`_examples`](https://github.com/lrstanley/bloom/tree/master/_examples) directory has complete
programs, in rough order of complexity. To run one, clone the repository and run it from that directory:

```console
git clone https://github.com/lrstanley/bloom
cd bloom/_examples
go run ./forms
```

Every example except `basics` and `standard` has a recording of its tour below, made by its tests.

## basics

Layouts printed with `Render`, without a program: every slot, `Min` and `Max`, `Collapsible`, gaps, `Justify`,
`Align`, `Space`, `Box`, wrapping text, `Centered`, and a layout inside Lip Gloss.

See also: [Sizing with slots](/layout/slots), [Text, boxes, and alignment](/layout/text-and-boxes).
[Source](https://github.com/lrstanley/bloom/tree/master/_examples/basics), or `go run ./basics`.

## standard

The usual shape of a program: a sidebar that's a `Layouter`, a plain component as the reader, a `Measurer` status
bar, and clicks.

See also: [Build your first layout](/getting-started/first-layout).
[Source](https://github.com/lrstanley/bloom/tree/master/_examples/standard), or `go run ./standard`.

## selection

![The selection example: lines of a log dragged over and copied, a rectangle of timestamps selected with alt held, a selection across a request's fields, words selected with a double click, all of the log selected and copied, and a token selected inside a dialog over the log](/demos/selection.webp)

Selecting text with the mouse and copying it. A drag selects a run of text, a drag with alt held selects a rectangle,
and a double or triple click selects a word or a line. It covers four kinds of node:

- A `Selectable()` viewport, whose selection takes lines scrolled out of sight and scrolls it when dragged past an edge.
- A column of fields, selected across a value and its label without the border.
- Styled text wrapped across rows, which is copied as one line.
- A dialog layer, whose selection stays inside it, holding a masked token that implements `TextSource` so the real
  token is copied.

See also: [Selecting and copying text](/input/selection), [Viewports](/layout/viewports).
[Source](https://github.com/lrstanley/bloom/tree/master/_examples/selection), or `go run ./selection`.

## golens

![The golens example: walking a Go project's call graph as a tree that opens to the right, a click selecting a function, its code between its callers and callees with the selected call marked, and a search jumping to a function by the shortest path from main](/demos/golens.webp)

A call graph explorer for any Go project, loaded with `golang.org/x/tools/go/packages`. The project's entry points
open into a tree of what each function calls, where only functions and wires glide as branches open, inside a
camera that scrolls with the selection. The code view opens from the selected function with an iris, highlights its
code with chroma in the theme's colors from bubbletint's `chromatint`, and marks each call of the selected callee. Pass it a directory, and optionally package patterns, as with `go run ./golens ..`
to explore bloom itself.

See also: [Layout animation](/motion/layout-animation), [Scrolling](/layout/scrolling), [Dialogs](/layers/dialogs).
[Source](https://github.com/lrstanley/bloom/tree/master/_examples/golens), or `go run ./golens [dir]`.

## Run and record them

Each example's comment at the top of `main.go` lists its keys. Most quit with <kbd>q</kbd> or <kbd>ctrl+c</kbd>.

The examples' tests drive each program end to end with [steep](/resources/related-libraries#steep), and record
the animations shown throughout these docs, as animated WebP. Run this from the repository root to record them
again, into `docs/public/demos`. It needs [ffmpeg](https://ffmpeg.org) on your `PATH`:

```console
task docs:demos
```

To record them somewhere else, set `STEEP_EXPORT_DIR`:

```console
STEEP_EXPORT_DIR=/tmp/demos task docs:demos --force
```
